# Reinforce 实验台

一个本地 WebUI，用来查看实验的中间过程和结果，以及从网页发起新训练。

它是**纯新增的一层视图**：只读写 `outputs/` 下的产物、以子进程方式调用既有的
`train.py` / `visualize.py`，不改动 `rl_common/` 与 `algorithms/` 的任何行为。

## 安装

WebUI 的依赖是独立的，跑实验不需要它们：

```bash
python -m pip install -r webui/requirements.txt
```

国内直连 PyPI 不稳时加镜像：

```bash
python -m pip install -r webui/requirements.txt \
    -i https://pypi.tuna.tsinghua.edu.cn/simple
```

## 启动

服务默认只监听 `127.0.0.1`（这个服务没有任何鉴权，不要暴露到局域网）。在无桌面的
服务器上，用 SSH 端口转发访问：

```bash
# 在服务器上启动
streamlit run webui/app.py

# 在你自己的机器上开隧道
ssh -N -L 8501:127.0.0.1:8501 <user>@<服务器>

# 然后浏览器打开
# http://127.0.0.1:8501
```

换端口：`streamlit run webui/app.py --server.port 8600`，隧道那侧端口要跟着改。

## 六个页面

| 页面 | 用途 |
| --- | --- |
| **运行总览** | 按环境分组。每个环境一张卡，卡内横向比较各算法族的最好回报；点卡片直接进入这个环境的对比页。 |
| **发起训练** | 一次选多个算法、多个种子，在同一个环境上批量启动。两个模式：「算法 × 种子」比算法，「算法 × 变体 × 种子」让同一个算法跑多份配置。每个组合是一个独立子进程，同一批共用一个时间戳。显卡默认自动分流，见下一节。 |
| **训练监控** | 任务统一看：这个 WebUI 启动的、以及你在命令行自己起的，都在这里。进度条、剩余时间、实时信号曲线、日志尾部。定时刷新可关。只展开**正在跑的**与**最近 5 个已结束的**，更早的收起来（注册表是只增不减的流水账，跑完一个变体批次就是六百多条）。 |
| **跨运行对比** | 先选环境，再选**一类改动**（基准 / 学习超参 / 环境扰动 / 训练预算 / 评估种子），看这一类下各算法**按算法分面**的学习曲线与**按族分组**的排名。见「跨运行对比怎么读」。 |
| **变体分析** | 同一算法的多份配置放在一起看：哪个参数动了之后确实变好/变差，以及这些结论有多可信。见「变体分析怎么读」。 |
| **运行详情** | 单个运行的**全程复盘**：第一个 tab「训练全程」一次给出主干曲线、跨面板联动的过程信号、动作分布、周期评估误差带、最终 10 个回合的逐回合得分、落地录像与离线四联图。后面六个 tab：训练信号、动作诊断、周期评估、轨迹回放（视频）、产物清单、配置与日志。还能从这里**重新出图 / 重录轨迹**。 |

## 同环境、多算法

各环境的奖励尺度完全不同（CartPole 满分 500，Pong 从 -21 起步），所以这个界面
**以环境为比较单位**：总览按环境分卡，对比页先选环境再排名，发起训练一次在同一个
环境上跑齐多个算法。

一次批量启动会展开成「算法 × 种子」个独立子进程，目录名形如
`outputs/<配置>_<算法>_s<种子>_<时间戳>`，同一批共用同一个时间戳，事后按名字就能
归组。算法多选框里自研与 `SB3-` 前缀的实现并列，两者读的是同一份超参 profile，
只有实现不同——这是做实现对照的前提。

## 变体模式：同一个算法跑多份配置

「算法 × 种子」回答的是「哪个算法好」。要回答「**同一个算法对什么敏感**」，把
「训练模式」切到「算法 × 变体 × 种子」：同一个算法跑多份配置——学习率换一档、
网络加宽一层、给环境加上风，再加上一条基准做对照。这一批的每一条运行都是独立的
子进程，走的是同一套显卡分流与启动链路。

**变体是一组点号路径覆盖。** 表里三列：`变体名 | 覆盖键 | 值`。同一个名字的几行
属于同一个变体；值按 YAML 语法解析，所以 `true` / `0.001` / `[64, 64]` 都能写。
覆盖键里的 `<ALGO>` 在展开时替换成该算法的 **profile 键**（去掉 `SB3-` 前缀），
于是同一条覆盖能同时用在自研 `PPO` 与 `SB3-PPO` 上——那正是「同超参、只换实现」
的对照所要求的。

**来源有三条，都只是往表里填行**：勾「从变体集文件载入」取
`config/variants/<配置名>.yaml` 里的条目；点「快捷预设」按维度填（学习超参 / 网络
宽度 / 环境扰动 / 训练预算 / 评估种子）；或者直接在表里手填，`num_rows="dynamic"`
可以加行删行。取消勾选会立刻把对应行从表里去掉——表是**派生**的，不是两处状态各自
为政。

**表格编辑只活在这一次会话里**，服务端不往仓库写文件。要留档就点「下载这份变体集」，
自己放进 `config/variants/`，下次就会出现在「从变体集文件载入」里。

**启动前会逐条校验，说清哪几条不会启动。** 校验只对**这一批真正选中的算法**做，
而不是配置里全部可跑的算法——否则十几条超参覆盖对 `REINFORCE`（它没有 profile）
全都不适用，会刷出一屏与本次批次无关的提示。会出现的提示有三类：

- 「在这些算法上都用不了，不会启动任何运行」——例如 `ent_coef` 在 `DQN` 上不存在；
- 「在某个算法上会跳过」——同一条覆盖对部分算法可用、部分不可用；
- 「已去重」——变体的覆盖恰好等于基准（例如 `lr-3e-4` 对 PPO 就是默认值），
  与基准并排跑只会白烧一张卡，还会在排行榜上并排显示两行一样的数字。

**目录名与实验名都带变体标识**：`outputs/<配置>_<算法>_s<种子>_<变体>_<时间戳>`，
`experiment.name` 写成 `<配置名>__<变体名>`。后者是事后识别变体身份的唯一依据——
排行榜、对比页、变体分析页都靠它把 `(算法, 变体)` 分成独立的一行。训练预算这类
变体（`budget-*`）还会各自带上自己的步数，而不是整批共用一个数。

## 跨运行对比怎么读

变体批次跑完之后，「跨运行对比」页面对的不是几十个运行而是几百个（本机当前
`LunarLander-v3` 上有 639 个：66 条基准 + 573 条变体）。把六百多个名字铺一屏、
两百多条条形堆一根轴上，除了「最高的那根最长」什么都读不出来。所以这一页的
顺序是**先选一类改动，再看图，最后看表**：

**第一道筛选是「对比维度」**，选项**按这个环境上真有的类别动态生成**，顺序是
「基准 → 学习超参 → 环境扰动 → 训练预算 → 评估种子 → 全部」，默认「基准」：

- **基准** —— 没套任何变体覆盖的运行。这是各算法本来的水平，也是唯一能跨算法
  对读的一组。
- **一个变体维度**（比如「学习超参」，即 `lr-* / ent-* / gamma-* / net-*`）——
  这一类的变体，**外加这些变体所属算法的基准**。基准必须跟着来：脱离基准，
  `lr-1e-3` 的回报既不知道算高还是算低，也不知道是它自己的贡献还是算法的底子。
- **全部** —— 六百个运行一起铺开。超过 60 个时会先给一句提示，这是刻意的动作。

一个还没跑过变体的环境不会出现「训练预算」这种点进去是空的档位。

**第二道筛选是「要看的算法」**，默认**按算法族轮换取 ≤8 个**，每族先取运行数最多的
那个实现。按族轮流而不是按目录顺序取前几个：变体批次里跑得最多的全挤在一个族
（PPO 有两套实现 + 七个学习超参档），按顺序取会落成「这个环境只有 PPO」。
粒度是**算法名**，所以同配置的多个种子整组进出，曲线不会凭空少一半种子。

**学习曲线是这一页的主视图**，不再是折叠在最底下的 expander，也不再是几百条线叠进
一张 matplotlib 图。它用 altair 分面：

- **一个面板一个算法**，面板里叠着它在当前这档下跑过的各份配置；
- **每个面板一根独立的 y 轴**。REINFORCE 的回报能到 −600，跟 DQN 共用一根轴会把
  后者压成一条直线；
- **跨面板共享一把刷子**：在任意一个面板里横向拖选一段步数，其余面板同步变暗，
  于是「同一个训练阶段里各算法分别在哪」可以直接对读；
- **线型区分版本**：同一个族里 `(实现, 变体)` 按字典序编号换线型（实线 / 虚 / 点 /
  点划），**基准是粗实线，变体是细的虚/点线**，同色代表同一个算法族。
- 没有曲线数据的运行会**在面板下面列一行说明**，而不是从图上静默消失——用户明明
  选了它却找不到，比少一条线更难排查。

altair 走浏览器渲染，所以图内的中文标题与图例不会变成方块（这一点与导出 PNG 的
matplotlib 路径不同，那条路的图内文字一律是英文）。

**算法排名按族分组**，不做成一面条形墙。族按 `REINFORCE → A2C → PPO → DQN → SAC
→ TD3`（学习顺序）排，每节的标题写明这一族里是哪几个实现（`PPO、SB3-PPO`）和
这一档下有哪些版本。分组不是排版偏好：

- 每根条的归一化轴**只在族内**。族与族的回报尺度不可比（离散环境里 SAC/TD3 高出
  一个量级），拿全局最大值归一化会让几个族都缩成一条线；轴归一到组内，长度才是
  可信的，族色只帮你把同一族的几根条认成一组。**族与族之间比数字，不比条长。**
- 同族里出现两个实现（`PPO` 与 `SB3-PPO`）时，能直接读出实现差异——这是本项目
  最核心的对照维度，混在两百行里会彻底消失。
- **基准条用饱和的族色，变体条用同色半透明**。同一个算法在这一档下的几条并排时，
  一眼能指出哪一条是参照物。
- 最后一个 `_BAR_LIMIT`（20 条）是防「全部」档重新变成条形墙的兜底。

**落地录像最多 12 个**（按最终回报取最好的，每个 `st.video` 都会让浏览器去拉一个
mp4，几百个一起放会把页面拖死）。

完整结果表在最后，仍带 CSV 导出；要插进报告里的静态叠加图在它下面——那是
matplotlib 路径，中文会变方块，所以图内文字是英文，与上面的交互图是两套实现。

## 「运行详情」的第一格：训练全程

「运行详情」页的第一个 tab 是**一次训练从头到尾的复盘**，顺序就是训练实际发生的
时间顺序。此前它是七格里各看一段，要回答「这次训练到底发生了什么」得在七个 tab
之间来回切、还得自己把时间轴对起来：

1. **主干曲线** —— `rollout/ep_rew_mean`（训练中每回合回报的滑动平均，点密、抖）
   与 `eval/mean_reward`（周期评估，点稀、噪声小）两格竖向对齐，共用一根时间轴。
2. **联动面板组** —— 回合长度、策略熵、KL、探索率…**按这份运行真的写出来的列
   动态出**（DQN 有探索率没有 KL，自研 REINFORCE 只有熵与策略损失），最多 8 格，
   共用一把刷子：拖一段步数，其余格同步聚焦。
3. **动作分布** —— 离散动作是各动作占比的堆叠面积，连续动作是各维度的均值。
   某个颜色被挤没了 = 策略退化成「永远选那一个动作」，这是与「训练不充分」分开的
   关键证据。
4. **周期评估的均値 ± 1σ** —— 误差带的宽度是同一档评估里几个回合之间的离散度，
   回答「上面那条均值线有多可信」。逐档明细收在 expander 里。
5. **最终评估的逐回合展开** —— `evaluation.json` 的 `episode_rewards` /
   `episode_lengths`：最后一次评估的 10 个回合各自得了多少分，配一条均值横线。
   「均值 132 但其中一回合是 −17」这种事只有展开才看得见。
6. **落地录像** —— 与「轨迹回放」tab 同一份数据（视频 / 首帧 / 前 500 行 CSV），
   直接摆在这里，不用再切 tab。
7. **离线四联图** —— `visualizations/training_results.png` 收进一个默认折叠的
   expander。它仍是可下载的附件，但不再占据第一屏。

数据缺哪一块就跳过哪一块并写一句「为什么没有」，不留白格也不静默消失。第二个 tab
「训练信号」保留为自由选信号的探索入口，与上面固定的面板组互补。

## 变体分析怎么读

「跨运行对比」回答「哪个算法好」；「变体分析」回答「**同一个算法把某个参数换一档
会怎样**」。它读的是一次 `variants.py` 调用产生的整批运行（见根 README 的
「变体实验」），按批次时间戳分组，同一批内的变体与同算法、同种子、同批次的基准配对。

这一页**故意把不确定性放在最前面**，因为这份数据的噪声很大，不先划线的话每一行
数字都会被读成效应。三条判读要点：

1. **先看零分布。** 配置逐字段相同的两次运行（`SAC` 与 `SB3-SAC` 在本项目里解析到
   同一个 SB3 实现，超参一字不差）拿来对比时，「3 种子平均 Δ」的 |Δ| 中位也有
   二三十、P90 近百。所以一个变体的 Δ 只有明显超过这个量级才值得当回事——
   单个 `z` 只是线索，**跨算法的方向一致**才是有力的证据。
2. **注意「跨型号」标记。** 本机混插了三种显卡。实测**同一型号的卡上跑同一个配置
   逐位相同，换型号才分叉**，而且这个分叉会被 RL 的混沌性放大。这份偏置是确定的
   硬件行为，事后无法从单个运行里剔除。所以每一行都标出「几个配对跨了型号」，
   完整的敏感性表里还有一个只用同型号配对的 `Δ均值（同型号）` 列——
   它干净但种子少，两个并排看，别只看一个。
3. **训练预算和评估种子单独归组。** `budget-*` 改的是训练步数，回答「多少步够用」，
   不能与 20 万步基准算敏感性 Δ——那会把「训练不足」读成「这个参数有害」。
   `evalseed-*` 不改训练、只换评估初始条件，它是这套分析的**安慰剂对照**：
   它的 Δ 全是噪声，正好用来估每个算法自己的噪声尺度 σ。

## 显卡怎么分

**卡数是探测出来的，不是写死的。** 每次打开「发起训练」都重新问一遍
`nvidia-smi`（5 秒缓存），页面上会说清楚探测到几张、按什么顺序排。机器上只有
一张卡、或者一张卡都没有，界面自己会跟着变。

**默认「自动分流」。** 选了自动之后，这一批的每个子进程依次落到候选卡上：候选卡
按**剩余显存从多到少**排，轮着用。显存快满（剩余 < 2048 MB）或利用率 ≥ 20% 的卡
会被跳过，旁边注明「跳过 GPU 2：已经在忙」。如果所有卡都在忙，会退回用全部卡——
挤一张忙卡也比让分配结果为空强。

**要留一张卡就别让它进候选池。** 只有在选了「自动分流」时才会出现「排除显卡」
多选框，勾掉的卡完全不参与分配。

**绑卡走 UUID，不走序号。** 子进程拿到的 `CUDA_VISIBLE_DEVICES` 是
`GPU-<uuid>`。原因是不这么干迟早会绑错卡：CUDA 默认的 `FASTEST_FIRST` 枚举顺序
和 `nvidia-smi` 的 PCI 顺序在混合卡型的机器上并不一致（本机 5880 Ada 和 4090D 就
是反的），按序号写死，你以为在用 0 号，实际跑在别的卡上。

因为 `CUDA_VISIBLE_DEVICES` 已经把那张卡映射成了子进程里的第 0 张，每个子进程的
`algorithm.device` 恒为 `cuda:0`。这看起来像「都挤在一张卡上」，其实不是——
`resolved_config.yaml` 里的 `cuda:0` 所在的那次运行，对应的是被隔离出来的那一张。

**没有 GPU 时退到 CPU。** `CUDA_VISIBLE_DEVICES=""` 启动服务（或这台机器本来就没
卡），界面会明说「没有检测到可用 GPU，将使用 CPU」，训练照常能发，只是走 CPU。

## 关于「发起训练」的几件事

**训练独立于页面运行。** 进程用 `start_new_session=True` 启动，关掉浏览器、
甚至重启 Streamlit 都不会打断训练。服务重启后靠 `webui/.state/jobs.json`
重新接管仍在运行的任务。

**不做终止功能。** 页面上会显示 PID，需要停止请手动 `kill <pid>`。

**输出目录默认平铺**成 `outputs/<配置>_<算法>_s<种子>_<时间戳>`，而不是嵌套的
`outputs/<配置>/<时间戳>/`。原因是 `compare.py` 只扫 `outputs/` 的一层
（`iterdir`），嵌套目录它永远发现不了——跑出来的实验会在终端对比里消失。
名字里带上算法和种子，顺带支持「同环境换算法/换种子」的对照实验。

**表单里的算法下拉来自当前配置的 `algorithm.profiles`**，不是全部可用算法。
选到没有对应 profile 的算法，训练会直接抛
`ValueError: No algorithm.profiles.X section exists`。同理，DQN 只支持离散动作、
SAC/TD3 只支持连续，这两类不匹配也会在点击之前就提示。

**「高级：任意配置覆盖」只列出这份配置里已经存在的标量键。** `apply_overrides`
刻意不允许新建键——拼错的键名如果被静默接受，训练会照常用默认值跑完，而你以为
改过了。所以拼错就直接报错。

**跟着配置走的控件，每个配置各是一套。** 换环境配置时，种子、步数、算法选择与
「高级覆盖」的控件都换成新配置自己的（内部实现是控件 key 带配置名后缀）。这不是
洁癖：控件在 Streamlit 里是**双向绑定**的，只把旧值从 `session_state` 里删掉挡不住
浏览器——前端还记着它，下一次任何重跑都会把旧值原样发回来。实测从 acrobot 切到
lunarlander 时，服务端当次算的、预览里显示的**都是 20 万步**，输入框里却还写着
10 万；只要再动一下任何控件，整批就会按 10 万跑。换成新控件之后前端没有旧值可发。
「计算设备分配」与「独立目录」不带后缀——它们与配置无关，切环境时本来就该留着。

## 实时进度是怎么来的

读 `logs/progress.csv`——SB3 的 CSV logger 每个 rollout 就 flush 一次。

**不能**用 `logs/episodes.csv`：那个文件是块缓冲的，训练结束才落盘，实时读永远是空的。

剩余时间三级回退：`time/fps` → `time/time_elapsed` → 用 `resolved_config.yaml`
的修改时间当墙钟起点。前两列只有 SB3 系的算法会写，自研 REINFORCE/A2C/PPO 没有。

## 列表页为什么快

列表页每次刷新都要**描述几百个运行**（当前 639 个）：读 `resolved_config.yaml`、
反查配置名、从 `progress.csv` 取最新步数。下面三件事是实测出来的瓶颈，都不是靠猜：

- **YAML 走 libyaml 的 C 加载器**（`yaml.CSafeLoader`）。纯 Python 的 `SafeLoader`
  读一份 `resolved_config.yaml` 要 10.1 ms，639 个运行就是 6.4 秒；C 版 1.2 ms。
- **最新步数只倒着读 `progress.csv` 的尾部**（256 KB），不整份解析。最大的一个
  progress.csv 有 5.6 MB / 4 万行，全量 `pd.read_csv` 一次 7.9 秒——只为了取一个
  步数。倒着读是先读到完整行就停，因此也不受「训练正在追加、最后一行是半截」影响。
- **配置名按目录名前缀反查**，而不是拿每份配置的默认输出目录去比对。WebUI 发起训练
  时一定会 `--set output.directory=outputs/<名字>`，默认目录永远对不上；而前缀匹配
  是纯字符串比较、639/639 命中，也顺带免掉了「建映射表要 `import torch`（1.9 秒）」。

结果是 `data.list_runs()` 从 23.4 秒降到 1.1 秒。扫描结果另外用
`st.cache_data(ttl=8)` 缓一层：Streamlit 点一下多选框就会重跑整个脚本，不缓存的话
在筛选器上连点几下就白等好几秒。想看刚结束的运行立刻上榜，点侧边栏的「清空缓存并刷新」。

## 常见问题

**页面报「没有发现任何运行」。**
「运行」的判据是目录里有 `evaluation.json`（跑完的标志）或 `resolved_config.yaml`
（已开工）。检查侧边栏的 `outputs 目录` 是否指对了。

**列表里少了某些运行。**
`output.timestamped: true` 会产生嵌套目录，本 UI 会扫两层，但 `compare.py`
不会。见上面关于平铺命名的说明。

**「运行详情」里不能重新出图。**
说明这次运行的 `output.directory` 是 `--set` 指定的，反查不到对应的配置名。
回命令行执行 `python visualize.py --config <配置> --set output.directory=...`。

**训练信号图是空的。**
`progress.csv` 的列集合每个算法都不一样，UI 只画这个运行真的有的列。
DQN 没有近似 KL，自研算法没有 FPS，这是正常的。

**改了绘图代码但图没变。**
Streamlit 的缓存没失效。点侧边栏的「清空缓存并刷新」。

**监控里老任务的「计算设备」对不上实际那张卡。**
`webui/.state/jobs.json` 里存的是启动当时算出的标签。改成 UUID 绑卡之前发起的任务，
记的是 `cuda:0` 这种按顺序的写法，在新枚举顺序下指向的物理卡可能不同。这只是历史
记录的显示问题，正在跑的训练不受影响（它们的环境变量在启动时就已经确定了）。

**启动时报 `missing ScriptRunContext`。**
这是 `streamlit.testing` 或裸模式下运行时的提示，正常使用不受影响。
